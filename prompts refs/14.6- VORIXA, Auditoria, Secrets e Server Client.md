# VORIXA, AUDITORIA 14.6: SECRETS E SERVER/CLIENT BOUNDARY

## OBJETIVO

Garantir que nenhum segredo ou lógica exclusivamente server-side seja exposto ao cliente.

## REGRA

Pesquisar de verdade.

Não declarar PASS somente porque `.env` existe.

## SECRETS

Pesquisar no código, Git, documentação, logs e bundles:

- FAL_KEY;
- DATABASE_URL;
- AUTH_SECRET;
- GOOGLE_CLIENT_SECRET;
- passwords;
- tokens;
- API keys.

## GIT

Verificar:

```bash
git status
git log --all --oneline -- .env
git ls-files
```

Não executar push.

## CLIENT BUNDLE

Verificar build e arquivos client-side.

Confirmar que secrets não aparecem.

## SERVER/CLIENT

Confirmar que ficam no servidor:

- Prisma;
- credenciais;
- providers;
- lógica financeira;
- chaves privadas.

Pesquisar `"use client"` e imports suspeitos.

## LOGS

Pesquisar se secrets podem aparecer em logs ou mensagens de erro.

## .env

Confirmar `.env` ignorado e `.env.example` sem credenciais reais.

## RELATÓRIO

Criar:

`security_audit_14_6_secrets.md`

Registrar evidências reais.

Executar:

```bash
npm run build
```

Ao terminar:

`AUDITORIA 14.6 CONCLUÍDA`

Não iniciar 14.7.
