# VORIXA, AUDITORIA 14.5: CSRF, CORS E SECURITY HEADERS

## OBJETIVO

Auditar exclusivamente proteção contra CSRF, CORS, clickjacking e headers.

## REGRA

Não presumir segurança.

Testar ou inspecionar com evidência.

Classificar cada item.

## CSRF

Auditar endpoints que alteram estado.

Verificar:

- cookies;
- SameSite;
- Origin;
- Referer;
- métodos;
- proteção específica quando necessária.

Não considerar automaticamente SameSite=Lax como prova suficiente para toda a aplicação.

## CORS

Testar:

- origem permitida;
- origem arbitrária;
- preflight;
- credenciais;
- métodos;
- headers.

## SECURITY HEADERS

Verificar resposta HTTP real quando possível:

- Content-Security-Policy;
- X-Content-Type-Options;
- Referrer-Policy;
- Permissions-Policy;
- Strict-Transport-Security;
- X-Frame-Options ou frame-ancestors.

## CLICKJACKING

Verificar se páginas autenticadas podem ser carregadas em iframe por origem arbitrária.

## RESULTADO

Diferenciar:

- header realmente presente;
- configurado no código;
- ausente;
- não aplicável.

## TESTES

Criar regressões para falhas.

Executar suíte e:

```bash
npm run build
```
