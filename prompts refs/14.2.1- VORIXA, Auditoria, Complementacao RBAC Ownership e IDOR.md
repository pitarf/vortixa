## REGRA OBRIGATÓRIA DE EXECUÇÃO

Cada item deve ser individualmente localizado, testado quando possível e registrado com evidência.

Classificar como:

- `TESTADO`
- `INSPECIONADO`
- `NÃO APLICÁVEL`
- `NÃO FOI POSSÍVEL TESTAR`

Não marcar PASS apenas porque existe UUID, middleware ou uma checagem aparente no código.

UUID não substitui autorização.
Middleware não substitui ownership no backend.
Frontend não é uma barreira de segurança.

Não inventar evidências.

Não alterar testes para fazê-los passar.

Se encontrar vulnerabilidade, registrar antes da correção e criar teste de regressão depois.

# 1. IDOR COM ID CONHECIDO

1. Criar Job pertencente ao USER_A.
2. Obter o `jobId` real.
3. Autenticar como USER_B.
4. Fazer requisição direta para `/api/tools/job/[id]` usando o ID real do USER_A.

Esperado: USER_B deve receber acesso negado mesmo conhecendo o ID.

Registrar usuário, ID, endpoint, método, status, resposta e evidência do ownership check.

# 2. IDOR INVERSO

Repetir:

USER_B cria recurso -> USER_A tenta acessar.

Testar Job e output, quando aplicável.

# 3. FILE OWNERSHIP

Pesquisar no projeto:

- `File`
- `fileId`
- `output`
- `outputUrl`
- `download`
- `storage`
- `/uploads/`
- URLs de storage
- endpoints de arquivos
- componentes de download

Se existir acesso a arquivo, USER_B deve tentar acessar arquivo do USER_A por ID, URL, Job, output e download.

Se realmente não existir acesso independente, registrar evidência concreta para `NÃO APLICÁVEL`.

# 4. OUTPUT OWNERSHIP

Criar Job/output do USER_A.

Como USER_B, tentar:

- consultar Job;
- obter output;
- acessar URL;
- acessar fileId;
- baixar resultado.

Nenhuma forma de acesso deve funcionar.

# 5. ACESSO DIRETO À URL

Se outputs/arquivos possuírem URL, verificar:

- pública ou privada;
- URL assinada;
- expiração;
- vínculo com usuário;
- possibilidade de reutilização por outro usuário.

Não expor credenciais.

# 6. JOB + FILE CRUZADOS

Quando houver Job e File, testar:

- Job A + File B;
- Job B + File A;
- Job A + output B;
- Job B + output A.

O backend deve validar as relações.

# 7. MANIPULAÇÃO DE USER ID

Testar diretamente nos endpoints:

```json
{"userId":"ID_DO_OUTRO_USUARIO"}
```

Repetir, se aplicável:

- `ownerId`
- `createdBy`
- `user_id`
- `owner_id`

A identidade deve vir da sessão, nunca do cliente.

# 8. MANIPULAÇÃO DE ROLE

Testar:

```json
{"role":"ADMIN"}
```

e, se aplicável:

- `isAdmin`
- `permissions`
- `roleId`

USER comum não pode obter privilégios.

# 9. MANIPULAÇÃO DE ISUNLIMITED

Testar:

```json
{"isUnlimited":true}
```

e equivalentes.

Nenhuma alteração de privilégio financeiro pode ser feita pelo request.

# 10. SERVER ACTIONS ADMINISTRATIVAS

Localizar todas as Server Actions administrativas.

Para cada uma:

1. identificar;
2. verificar autenticação;
3. verificar role;
4. testar como USER;
5. confirmar autorização dentro da própria Action;
6. confirmar que não depende apenas de UI ou middleware.

Uma Server Action deve permanecer segura quando chamada diretamente.

# 11. ENDPOINTS ADMINISTRATIVOS

Localizar todos `/api/admin/*`.

Para cada um, verificar autenticação, autorização, role, método, IDs e ownership quando aplicável.

Testar acesso como USER.

# 12. API DIRETA

Executar os testes sem utilizar a interface, usando cURL, fetch ou testes HTTP quando apropriado.

Comprovar que a segurança está no backend.

# 13. MÉTODOS HTTP

Para endpoints desta auditoria, testar métodos não previstos quando aplicável:

GET, POST, PUT, PATCH e DELETE.

Registrar 405 ou comportamento equivalente.

# 14. RECURSOS INEXISTENTES

Testar ID inexistente, malformado, formato inválido e vazio.

Verificar status, mensagem e ausência de stack trace/dados internos.

# 15. TESTES DE REGRESSÃO

Criar ou ampliar testes para:

1. USER_A -> Job do USER_B;
2. USER_B -> Job do USER_A;
3. output de terceiro;
4. File de terceiro, quando aplicável;
5. Job + File incompatíveis;
6. userId manipulado;
7. role manipulada;
8. isUnlimited manipulado;
9. Server Action administrativa por USER;
10. endpoint administrativo por USER.

Executar toda a suíte e confirmar que nada regrediu.
